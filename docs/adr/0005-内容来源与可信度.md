# ADR-0005：内容必须带来源，不确定就标「待核实」

- 状态：已接受
- 日期：2026-10-26
- 决策者：P1、P4、指导老师

## 背景

文化类内容最容易出的问题不是"不准"，而是"看起来很像真的"：模型编出一段像模像样的历史渊源，用户信了，出了事没人担得起。开放时间、票价这类信息同理——写死在页面上，过期就是误导。

## 决策

1. 每条文化说明、开放时间、票价都必须挂在**来源**上：`place_fact` 行带 `source_id`，`source` 行存 URL + 抓取时间 + 类型（官方/媒体/论文/UGC）。
2. 没有来源的事实**可以存在**，但 `confidence` 必须是 `unverified`，页面必须显示「待核实」标签。
3. 行程规划输出里，任何一条无法核对的安排都要保留 `unverified` 标记，**不许**为了提高"完成度"而默认成确定值。
4. 提交审核时，`unverified` 项超过阈值（暂定 50%）时给审核员显式警告，但不阻止提交——阻止会让人为了过审而乱填来源。

## 理由

- 对答辩：能当场点开来源链接，比任何"我们用了大模型"的说法都更有说服力。
- 对用户：标注不确定性的产品比假装精确的产品更可信，也减少了"到了发现闭馆"的投诉。
- 对开发：`confidence` 字段一旦定了，前端的展示逻辑、审核的检查点、测试的断言都有了统一依据。

## 后果

- 好：内容质量有下限；数据来源可审计；后续接真实数据源时字段不用改。
- 坏：录入成本高，早期内容会很少。**对策**：首版只做长沙 30–50 个点位，宁少勿滥。
- 坏：`unverified` 会被滥用成"懒得查"。**对策**：审核任务卡里把"来源覆盖率"列为必检项，答辩演示里专门看这个字段。
