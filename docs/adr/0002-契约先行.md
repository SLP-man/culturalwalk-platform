# ADR-0002：契约先行，OpenAPI 是唯一真源

- 状态：已接受
- 日期：2026-10-26
- 决策者：P1、P3、P4

## 背景

前后端并行开发时最常见的返工：后端字段改名，前端类型没跟上，运行时才炸；或者两个人对"分页参数叫 page 还是 cursor"理解不一致。

## 决策

1. `docs/api/openapi.yaml` 是**唯一事实源**。改端点必须先改它。
2. 前端类型由它生成（`packages/contracts/src/types.ts`），**禁止手写 DTO interface**。
3. CI 跑两个检查：契约自身的语法/引用/幂等头（`scripts/check_contract.py`），以及"契约改了但没重新生成类型"（`gen.mjs --check`）。
4. 后端路由用 FastAPI，因此 OpenAPI 也能从代码反推——但我们**不**允许"代码即契约"，否则前端又得等后端写完。

## 理由

- 生成类型的成本是几秒钟，手写 interface 的成本是每次改动后的对齐会议。
- 契约文件在 PR 里是可见的 diff，评审时能直接看出"这个接口的语义变了"。
- 契约先行逼着大家先把资源模型想清楚，而不是边写边改表。

## 后果

- 好：前端可以对着 mock 先写页面；后端可以对着契约写测试；字段改名会立刻在 CI 报错。
- 坏：每次改契约要跑一次生成并提交 `types.ts`。**对策**：`pnpm gen` 写进 README 和 PR 模板，CI 拦住忘提交的人。
- 坏：契约容易写得太理想（字段很多），实现时偷工减料。**对策**：本期的契约只覆盖演示链路必须的字段，LATER 的东西不写进去。
