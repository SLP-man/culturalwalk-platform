## 1. 答辩演示（6 分钟版）

**准备**：演示前 10 分钟执行 `docker compose up -d` + `python scripts/seed.py` + 预跑一次规划（缓存兜底），关闭通知弹窗，开好两个浏览器窗口（普通用户 / 管理员）。

| 时间 | 操作 | 讲解词（要点） | 翻车兜底 |
|---|---|---|---|
| 0:00–0:40 | 打开首页，滚动路线卡片，点主题筛选「民俗」 | 「访客不用登录就能按文化主题找路线；每条路线都标了文化主题和费用区间」 | 用预置的 10 条路线，别现场搜生僻词 |
| 0:40–1:30 | 点开「岳麓山—湖南大学—橘子洲」详情 | 「每个点位都有文化说明，展开能看到来源；开放时间和票价标了最后核实日期，不确定的写『待核实』，不装成确定的」 | 来源折叠面板提前点开过一次 |
| 1:30–3:00 | 进「规划」，填长沙 / 2 天 / 3 人 / 1000 元 / 历史+民俗 → 生成 | 「系统先检索有来源的地点，再按时间和地理邻近组排，然后自查超预算和闭馆，最后逐条核对来源——四步各自留痕，界面上能看到每一步」 | 演示态用预生成结果（标『示例』），并说明真实生成在后台跑 |
| 3:00–3:40 | 看行程结果：天数、时间、交通方式、费用区间、「待核实」标记 | 「注意这里不承诺精确到分钟，也不承诺实时营业，因为数据源还撑不住这个精度——这是有意为之，不是没做完」 | — |
| 3:40–4:20 | 点「发布为路线」→ 生成草稿 → 补一条来源 → 提交审核 | 「AI 只能生成草稿，不能直接发布；发布必须经过人和审核」 | 提前准备一条已补好来源的草稿 |
| 4:20–5:20 | 切管理员 → 审核队列 → 看 diff → 退回（写理由）→ 再通过 → 发布 → 回前台刷新可见 | 「审核看的是某个具体版本的 hash，通过后发布的也是这个版本，中途内容被改过就发不出去」 | 退回那步如果卡住，直接走通过 |
| 5:20–6:00 | 另一个账号评论 + 收藏 → 管理员下线 → 前台刷新 404 | 「下线立即生效，且留了原因和审计记录；谁在什么时候审了哪个版本都能查」 | — |

**一句话收尾**：「这条链路上每一步都留了证据：内容有来源、版本有 hash、审核有理由、操作有审计。」

## 2. 验收清单

### 2.1 功能验收（答辩前必须全绿）

- [ ] 注册 → 登录 → 退出，token 过期后自动刷新
- [ ] 访客能浏览列表、筛选、搜索，未发布内容搜不到
- [ ] 路线详情显示节点顺序、文化说明、来源、费用区间
- [ ] 「待核实」标记出现在所有 confidence != verified 的条目上
- [ ] 新建草稿 → 加 3 个节点 → 调顺序 → 保存，刷新后顺序不变
- [ ] 提交审核后草稿锁定，不能改
- [ ] 管理员领取任务 → 通过 → 发布，前台立即可见
- [ ] 退回必须填理由，作者收到通知，草稿回到可编辑
- [ ] 下线后前台 404，且审计里有记录
- [ ] 规划：缺字段时返回明确提示，不是 500
- [ ] 规划结果可保存、可分享链接、可转草稿
- [ ] 评论、作者置顶一条、收藏/取消收藏
- [ ] 个人主页显示用户名与已发布路线

### 2.2 权限负例（必须逐条验证，不只是「应该」）

| # | 场景 | 期望 |
|---|---|---|
| 1 | 未登录提交草稿 | 401 |
| 2 | 用户 A 改用户 B 的草稿 | 403 |
| 3 | 普通用户调 `/review/tasks` | 403 |
| 4 | 普通用户调 `/audit-logs` | 403 |
| 5 | 管理员审自己提交的路线 | 403 `SELF_REVIEW_FORBIDDEN` |
| 6 | 未领取任务的人做 decision | 403 |
| 7 | 用过期 token 访问 | 401 且提示刷新 |
| 8 | 发布时 hash 与版本不符 | 409 |
| 9 | 并发改草稿（`If-Match` 旧值） | 412 |
| 10 | 两人同时 claim 同一任务 | 一人 200 一人 409 |
| 11 | 重复提交同一草稿 | 409，不产生第二个版本 |
| 12 | 引用未扫描完成的图片 | 422 |

### 2.3 数据与一致性

- [ ] 一条路线同时只有一个 `PUBLISHED` publication（构造并发测试）
- [ ] 同一版本只能被投稿一次（唯一索引生效）
- [ ] 审计表只增不改（用 UPDATE 语句试，应无权限或触发失败）
- [ ] 迁移在空库和旧库都能跑通
- [ ] 种子脚本重复执行不产生重复数据（幂等）

### 2.4 可演示性

- [ ] 断网时前端给明确提示，不是白屏
- [ ] LLM 超时 → 界面显示「生成失败，重试」而非卡死
- [ ] 首页首屏 ≤ 2s（本地）
- [ ] 手机尺寸（375×812）下无横向滚动
- [ ] 答辩机执行 `bash scripts/demo_up.sh` 能一键起全套

## 4. 已知不做（答辩被问就照这个回答）

| 会被问 | 回答 |
|---|---|
| 为什么不做实时营业/路况 | 数据授权与稳定性成本高于当前阶段收益；行程精度故意停在「顺序+时长+区间」，避免给用户虚假精确感 |
| 为什么不做多人同时编辑 | 与「版本不可变 + 审核看具体 hash」冲突，收益低；改成人人可投稿自己的路线 + 作者采纳建议 |
| 为什么单城 | 先把一个城市的文化资料做扎实，验证「有依据的推荐」这个核心假设，再复制 |
| 为什么不用微服务 | 当前团队与流量都不需要，模块化单体保留拆分边界，等真有独立扩缩容需求再拆 |
| AI 会不会乱编 | 有来源才给确定值，没来源标「待核实」；AI 只能产草稿，发布必须过人 |
