# 接口契约规范

> **唯一事实源**：`docs/api/openapi.yaml`。本文档解释约定，字段以 yaml 为准。
> 前缀 `/api/v1`。改接口 = 先改 yaml + 提 PR + 通知前端，不许「后端先写完再说」。

---

## 1. 通用约定

### 1.1 认证

- `Authorization: Bearer <access_token>`
- access token 15 分钟，refresh token 14 天，refresh 时轮换旧的
- 未登录访问需要登录的接口 → `401`；已登录但无权限 → `403`（两者不能混淆）

### 1.2 幂等

所有 `POST`（登录注册除外）必须带请求头：

```
Idempotency-Key: <uuid>
```

同 key 重复请求返回**首次结果**（含状态码），不重复执行。服务端存 key → 响应 24 小时。

### 1.3 并发控制

编辑类接口（`PATCH /route-drafts/{id}`）必须带：

```
If-Match: <lock_version>
```

不匹配 → `412 Precondition Failed`，前端提示「内容已被更新，请刷新」。

### 1.4 错误包

所有非 2xx 响应体：

```json
{
  "error": {
    "code": "ROUTE_NOT_PUBLISHED",
    "message": "该路线尚未发布",
    "request_id": "req_01H...",
    "details": [{"field": "version_id", "reason": "not_current"}]
  }
}
```

错误码用大写下划线，前端按 `code` 分支，**不要**按 message 文案判断。

### 1.5 分页

```
GET /routes?cursor=<opaque>&limit=20
```

```json
{"items": [...], "next_cursor": "eyJpZCI6..."}
```

`limit` 默认 20，上限 50。**不用 offset**（数据会变）。

### 1.6 时间与坐标

- 时间一律 ISO 8601 带时区：`2026-10-23T18:00:00+08:00`
- 坐标 `lat`/`lon`，WGS84；展示前由前端按底图坐标系转换
- 金额用整数「分」+ `currency: "CNY"`，不用浮点

### 1.7 版本与缓存

- 公开详情返回 `ETag`（= content_hash），`If-None-Match` 命中返回 `304`
- 公开接口 `Cache-Control: public, max-age=60`，下线时由服务端发 `purge`

## 2. 端点清单

图例：🔓 公开 / 👤 登录 / 🛡 管理员及以上

### 2.1 认证与账号

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/auth/register` | 🔓 | 用户名 + 密码；返回 token |
| POST | `/auth/login` | 🔓 | 失败统一返回「用户名或密码错误」 |
| POST | `/auth/refresh` | 🔓 | 带 refresh token，返回新一对 |
| POST | `/auth/logout` | 👤 | 吊销当前 session |
| GET | `/users/me` | 👤 | 自己的资料与角色 |
| GET | `/users/{user_id}/profile` | 🔓 | 用户名、简介、已发布路线 |

### 2.2 地点资料

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/places` | 🔓 | `?q=&district=&tag=&limit=` |
| GET | `/places/{place_id}` | 🔓 | 含 facts 与 sources |
| POST | `/places` | 🛡 | 新增地点（编辑用） |
| POST | `/places/{place_id}/facts` | 🛡 | 加一条事实 + 来源 |

### 2.3 路线草稿（作者侧）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/route-drafts` | 👤 | 只返回自己的 |
| POST | `/route-drafts` | 👤 | 新建草稿，`channel` 由后端定（用户 = user） |
| GET | `/route-drafts/{id}` | 👤 | 非本人 403 |
| PATCH | `/route-drafts/{id}` | 👤 | 需 `If-Match`；只有 `EDITING` 可改 |
| DELETE | `/route-drafts/{id}` | 👤 | 只有 `EDITING` 且未发布过 |
| PUT | `/route-drafts/{id}/nodes` | 👤 | **整表替换**有序节点数组 |
| POST | `/route-drafts/{id}/submit` | 👤 | 冻结版本 + 建投稿 + 建审核任务（一个事务） |
| POST | `/route-drafts/{id}/withdraw` | 👤 | 撤回投稿，回到 `EDITING` |

> 为什么节点用整表替换：排序是核心语义，逐条增删容易产生空档位和并发错乱。整表替换天然幂等。

### 2.4 审核与发布（管理侧）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/review/tasks` | 🛡 | `?state=OPEN\|CLAIMED\|COMPLETED` |
| POST | `/review/tasks/{id}/claim` | 🛡 | 抢占；已被抢 → 409 |
| POST | `/review/tasks/{id}/release` | 🛡 | 释放回 OPEN |
| POST | `/review/tasks/{id}/decision` | 🛡 | `{action: approve\|request_changes\|reject, reason}` |
| GET | `/submissions/{id}` | 🛡 | 含版本 diff 所需的两侧快照 |
| POST | `/submissions/{id}/publish` | 🛡 | 必须附 `version_id` + `content_hash` |
| POST | `/publications/{id}/unpublish` | 🛡 | 必须附 `reason` |

**decision 约束**：`request_changes` 和 `reject` 的 `reason` 必填（≥10 字）；不能审自己的投稿（403 `SELF_REVIEW_FORBIDDEN`）。

### 2.5 公开路线（访客侧）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/routes` | 🔓 | `?q=&theme=&duration=&budget_max=&channel=&cursor=` 只返回已发布 |
| GET | `/routes/{id}` | 🔓 | 404 同时覆盖「不存在」和「未发布」 |
| GET | `/routes/{id}/versions` | 🛡 | 历史版本列表（管理端用） |
| GET | `/routes/{id}/comments` | 🔓 | 置顶在前，其余按时间倒序 |
| POST | `/routes/{id}/comments` | 👤 | 正文 ≤ 500 字 |
| POST | `/comments/{id}/pin` | 👤 | 只有路线作者；每条路线最多 1 条置顶 |
| POST | `/routes/{id}/favorite` | 👤 | 幂等 |
| DELETE | `/routes/{id}/favorite` | 👤 | 幂等 |

### 2.6 行程规划

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/plans` | 👤 | 提交条件 → 返回 `202 + run_id`，异步生成 |
| GET | `/plans/{id}` | 👤 | 含 `state` 与 `steps[]`，前端轮询 |
| GET | `/plans` | 👤 | 我的行程列表 |
| POST | `/plans/{id}/to-draft` | 👤 | 转成路线草稿，返回 `draft_id` |
| DELETE | `/plans/{id}` | 👤 | 删自己的行程 |

**`POST /plans` 请求体**

```json
{
  "city": "changsha",
  "days": 2,
  "people": 3,
  "budget_total": 100000,
  "include_lodging": false,
  "start_point": {"lat": 28.19, "lon": 112.98, "label": "五一广场"},
  "day_parts": ["morning", "afternoon", "evening"],
  "themes": ["历史", "民俗"],
  "transport": ["walk", "metro"],
  "pace": "normal"
}
```

**缺信息时不要瞎猜**：返回 `422` + `code: PLAN_INPUT_INCOMPLETE` + `details` 列出缺哪几项，前端弹追问。

### 2.7 媒体

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/media/intent` | 👤 | 返回预签名 URL + `asset_id`（zone=quarantine） |
| POST | `/media/{id}/complete` | 👤 | 客户端上传完通知服务端，入队扫描 |
| GET | `/media/{id}` | 👤 | 只有 `CLEAN` 才有可公开访问的 URL |

### 2.8 通知与审计

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/notifications` | 👤 | 只返回自己的 |
| POST | `/notifications/{id}/read` | 👤 | 幂等 |
| GET | `/audit-logs` | 🛡 | `?object_type=&object_id=&actor_id=` |
| GET | `/health` | 🔓 | `{"status":"ok","version":"..."}` |

## 3. 状态码约定

| 场景 | 码 |
|---|---|
| 成功创建 | 201 |
| 异步已接受 | 202 |
| 成功无内容 | 204 |
| 参数错误 | 400 |
| 未登录 / token 过期 | 401 |
| 已登录但无权限 | 403 |
| 不存在 / 不可见（含未发布） | 404 |
| 状态不允许此操作 | 409 |
| 并发冲突 | 412 |
| 业务校验失败（可提示字段） | 422 |
| 限流 | 429 |

## 4. 前端如何用契约

```bash
# 生成 TS 类型（在 packages/contracts）
pnpm gen            # openapi.yaml -> src/types.ts
```

- 页面里只 import 生成的类型，**禁止手写重复的 interface**
- 后端改字段必须同步改 yaml；CI 会跑 `pnpm gen --check`，不一致直接失败
- 分片规则：模块负责人只改自己模块的 `paths` 段，冲突时 P1 裁决
