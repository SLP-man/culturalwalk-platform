# 新手入门指南（DSH 版）

> 给"没写过代码、没用过 GitHub"的组员。
> 读完你只需要记住一件事：**你负责说清楚要什么、验收做得对不对；写代码、跑命令、传 GitHub，都交给 DSH 里的 agent。**
> 你不需要背命令，不需要学 git，也不需要懂什么叫分支。

---

## 1. 你的角色：你是"提需求的 + 验收的"，agent 是"动手的"

| 谁 | 干什么 |
|---|---|
| **你** | ① 从待办里领一张卡 ② 用大白话告诉 agent 要什么 ③ 跑起来自己点一遍看对不对 ④ 点一下合并按钮 |
| **DSH 里的 agent** | 读代码、写代码、装依赖、跑测试、提交、推送、开 PR、修 CI |
| **GitHub** | 存档 + 待办板 + 自动检查（相当于"云端共享文件夹 + 任务看板 + 自动批改"） |

所以你**每天真正要做的动作只有 4 个**：说话、看结果、点两下（认领 / 合并）。下文全部围绕这四个动作写。

---

## 2. 两个窗口，别搞混

```
┌─────────────────────────┐        ┌──────────────────────────┐
│  DSH 窗口（你打字的地方） │        │  GitHub 网页（浏览器）     │
│                         │        │                          │
│  你说：帮我做 #12 这张卡  │  ───▶  │  待办列表（Issues）       │
│  agent：写代码、跑起来    │        │  你提的改动（PR）         │
│  你：打开网址点一点验收   │  ◀───  │  自动检查结果（✅/❌）     │
└─────────────────────────┘        └──────────────────────────┘
```

- **DSH 窗口**：像跟一个很听话但不会读心术的实习生聊天。你说得越具体，它做得越对。
- **GitHub 网页**：你不用学它怎么用，只需要会打开两个链接（待办列表 / 你那条改动），会点绿色按钮。

---

## 3. 名词表：只有 8 个词，够用了

| 词 | 大白话 | 你需要做什么 |
|---|---|---|
| 仓库 | 这个项目的云端文件夹 | 不用管，agent 会同步 |
| Issue（待办） | 一张任务卡，比如"做登录功能" | 领一张（或让 agent 帮你领） |
| 分支 | 你改动时用的"草稿副本"，不影响正式版 | 不用管 |
| 提交 / 推送 | 把改动存档并传到云端 | 不用管 |
| **PR（Pull Request）** | 「我改好了，请并进正式版」的申请单，附带自动检查结果 | 看结果 + 点合并 |
| CI（自动检查） | 每次有人提交，系统自动跑一遍格式/测试/接口检查 | 看到红叉就告诉 agent |
| main（正式版） | 大家共用的那一份，**永远要能跑** | 你不能直接改它，只能通过 PR |
| 迁移 | 改数据库表结构的记录 | 不用管，但**别让 agent 改旧的迁移文件** |

> 记住一条就够了：**改动永远走 PR，不进 PR 的东西等于没做。**

---

## 4. 第一次准备（只做一次，约 30 分钟）

### 4.1 三样东西齐不齐

- [ ] 电脑上装了 **DSH**，能打开窗口跟 agent 对话
- [ ] 有 **GitHub 账号**（没有就去 github.com 注册，1 分钟，邮箱验证一下）
- [ ] 被拉进仓库：把你的 GitHub 用户名发给 **P1**，他在仓库 Settings → Collaborators 里邀请你，你到邮箱点 Accept

> 没被邀请的话，你后面推代码、合并都会被拒绝。这一步别跳。

### 4.2 把项目弄到自己电脑上

在 DSH 窗口里直接说（复制这句）：

```
帮我把 https://github.com/SLP-man/culturalwalk-platform 克隆到 D:\文化行走 这个文件夹，
然后告诉我这个项目是干什么的、怎么在本机跑起来。
```

agent 会自己下载、装依赖。它做完会告诉你一个网址（一般是 `http://localhost:5173`），浏览器打开能看到首页就说明成功。

### 4.3 让 agent 接上你的 GitHub 账号

```
我需要能把我改的代码推到 GitHub，帮我配好登录。
如果需要我在浏览器点授权，告诉我什么时候点。
```

按它说的做（通常是弹一个网页，点一下"同意"）。**配一次，以后不用再弄。**

### 4.4 三个"卡住了"的信号

出现下面任意一种，别硬扛，截图发给 P1：

| 现象 | 大概率原因 |
|---|---|
| agent 说"连不上 github.com" | 网络/代理问题，让它"试试用系统代理"或"改用 api.github.com" |
| 推代码时提示 403 / Permission denied | 你还没被加成 Collaborator，或授权没点成功 |
| 跑起来报错一堆红色字 | 前面某步没装好，把红字原文贴给 agent，说"帮我修" |

## 5. 领活：只有一步（也可以让 agent 代劳）

### 5.1 看还有哪些活

打开 👉 <https://github.com/SLP-man/culturalwalk-platform/issues>

每条是**一张任务卡**，标题长这样：`[ID-02] 注册/登录/退出`。
前面的 `ID-02` 是卡号，`ID` 是模块缩写（`ID`=账号、`RS`=路线、`PL`=规划、`CM`=社区、`FE`=网页…）。

**筛出"我的"**：点上方 `Label` → 选你的模块（比如 `identity`），或者选 `M1`（第一阶段要做的）。

### 5.2 认领

最简单：在 DSH 里说

```
我要做第 12 号任务（issue #12），先帮我认领，然后把这张卡的要求翻译成人话给我听。
```

agent 会替你在 GitHub 上把这张卡指派给你，并告诉你"要做啥、怎么算做完"。

> 想自己点也行：打开那条 issue，右边 `Assignees` → 点自己的名字。

### 5.3 卡里那几行字怎么读（用大白话）

| 卡里写的 | 意思 |
|---|---|
| **输出**：`router.py, service.py` | 这次要动的文件，就这些，其他别碰 |
| **验收**：`错误密码返回 401` | 怎么算做完——你能亲手试出来的现象 |
| **依赖**：`ID-01` | 得先等另一张卡做完，否则你没法开始 |
| **估计**：2 人天 | 大概两天的活，超太多就在卡下面说一声 |
| **负责角色**：P2 | 建议谁做，不强制 |

---

## 6. 让 agent 干活：怎么说，它才不会跑偏（最重要的一节）

### 6.1 万能开场模板（把方括号换成你的）

```
我要做 issue #[卡号]「[卡名]」。

要求：
1. 先读这道卡的要求和 docs/ 里的相关文档，用 3 句话说清楚你打算怎么做，等我确认再动手。
2. 只改这张卡"输出"里提到的文件，不要动别的模块。
3. 做完要满足卡里的"验收"条件，并且跑一遍项目自带的检查（lint、测试、类型）。
4. 全程不要直接改 main 分支，也不要改已经存在的数据库迁移文件。
5. 做完告诉我三件事：改了什么、怎么验证、我该打开哪个网址点哪里。
```

**为什么每一条都要有**：

| 那句话 | 防的是什么坑 |
|---|---|
| 先说方案再动手 | 否则它一上来写 500 行，方向错了全废 |
| 只改这几个文件 | 否则它顺手"优化"了别人的代码，冲突全来了 |
| 满足验收 + 跑检查 | 否则它说"完成了"但一跑就崩 |
| 不碰 main、不碰旧迁移 | 这两样一碰，全组的项目就坏了 |
| 告诉我怎么验证 | 你才有办法判断它是不是真做完了 |

### 6.2 三种中途追加的话

| 你想说 | 怎么说 |
|---|---|
| 它理解错了 | 「停。我说的不是 X，是 Y。先复述一遍你理解的，再继续。」 |
| 跑起来报错 | 「这是我点的时候看到的报错：[粘贴原文]。先别改代码，告诉我原因，再给方案。」 |
| 它想顺手改别的 | 「这次只做这张卡。别的先记下来，跟我说一声就行，不要动手。」 |

### 6.3 千万别这么说话

| ❌ 别说 | 为什么 | ✅ 改成 |
|---|---|---|
| 「帮我优化一下」 | 它不知道优化什么，会乱改一大片 | 「登录接口现在要 2 秒，帮我查为什么慢，先只报告原因」 |
| 「把登录和注册都做了吧」 | 一次做太多，出错你不知道是哪块 | 一次一张卡 |
| 「随便实现就行」 | 会写出看起来能用、其实有漏洞的代码 | 「按卡里的验收做，负例也要测」 |
| 「你自己决定」 | 决定错了返工更贵 | 「两个方案各有什么代价？我选一个」 |

## 7. agent 说"做完了"，你怎么判断（不用懂代码）

### 7.1 要它拿出三样证据

```
你说做完了，给我三样东西：
1. 我打开哪个网址、点哪几个地方能看到效果；
2. 你跑检查的结果（把那几行输出贴出来）；
3. 你改了哪几个文件（列文件名）。
```

### 7.2 你自己上手点一遍（5 条检查）

拿"登录"举例，你打开 `http://localhost:5173` 之后的检查清单：

| 检查 | 怎么试 | 合格标准 |
|---|---|---|
| 能用吗 | 输对用户名密码点登录 | 能进到首页/我的页面 |
| 错了会提示吗 | 故意输错密码 | 页面有中文提示，不是白屏、不是一堆英文报错 |
| 该拦的拦住了吗 | 没登录直接访问"我的路线" | 被弹回登录页（这是**正确**行为，别让 agent"修好"） |
| 中文正常吗 | 看页面上的字 | 没有乱码、没有 "null"、没有 `undefined` |
| 数据是自己的吗 | 换个账号登录 | 看不到别人的草稿 |

**这 5 条你不需要懂代码就能判断，但它比任何测试都管用。**

### 7.3 不满意就直说，别自己动手改

```
第 2 条不行：密码错了之后页面只闪一下，没有任何提示。
我要的效果是：输入框下面出现一行红字"用户名或密码错误"。
改完再让我看。
```

## 8. 收尾：点一次绿色按钮（你唯一的 GitHub 操作）

agent 做完会把改动打包成一条 **PR**，并把链接发给你，形如
`https://github.com/SLP-man/culturalwalk-platform/pull/18`。

打开它，你会看到两种结局：

### ✅ 全绿：点合并

页面下方有几个检查项（`backend` / `frontend` / `contract` / `compose`），全打绿勾 →
点绿色 **Merge pull request** → 再点 **Confirm merge**。完事，那张任务卡会自动关闭、打勾。

### ❌ 有红叉：别点，回去找 agent

```
PR #18 的 CI 红了，红的是 frontend 那个。帮我看看原因并修好，修好再告诉我。
```

**红叉时千万别点合并**——那等于把坏掉的车开上高速。

### 需要别人点同意怎么办

现在仓库设了"必须 1 个人同意才能合并"。你就把 PR 链接发到群里，任意一个组员打开点 **Approve** 就行。
嫌这一步麻烦，可以让 P1 把这个限制关掉（我建议留着，至少能防住一半的低级错误）。

## 9. 拿 `ID-02 注册/登录` 走一遍完整流程（示范）

这是给全组看的样板：一张卡从"领"到"合并"，你实际会经历什么。

| 阶段 | 你做什么 | 你看到什么 |
|---|---|---|
| ① 领卡 | 在 DSH 说「我要做 #12，帮我认领并翻译成人话」 | agent：这张卡要做注册/登录/退出三个接口；验收是"密码对了给凭证，密码错了返回 401" |
| ② 对齐方案 | 等它说方案，你只判断一件事：**它说的是不是你要的** | agent：先建 users 表 → 写三个接口 → 加 5 条测试 → 跑通后开 PR |
| ③ 它干活 | 你不用管；它可能会问你要"管理员账号初始密码设成什么" | 一般十几分钟到一小时 |
| ④ 验收 | 打开它给的网址，用**你刚注册的账号**登录一次、故意输错一次 | 对：能进首页；错：有中文提示 |
| ⑤ 看检查 | 打开 PR 链接 | 四个绿勾 |
| ⑥ 合并 | 点 **Merge pull request** | 页面显示 Merged，那张卡自动关闭 |
| ⑦ 出问题 | 如果第 ④ 步不对：把现象说清楚让它改，别自己改 | — |

**这张卡做完，你在网页上能看见的变化**：右上角从"登录/注册"变成你的用户名；点进去能看到你的主页；没登录时点"我的路线"会被弹回登录页；刷新页面还是登录状态。

**为什么先做它**：后面几乎所有功能都要先"知道你是谁"（发路线要知道作者、收藏要知道是谁、审核要知道你是不是审核员）。所以这 4 张卡是地基。

## 10. 十条"别做"（都是 AI 编程最容易踩的坑）

1. **别让 agent 直接改正式版（main）**——一切都走 PR。
2. **别一次让它做三张卡**——出错时你不知道是哪块坏的。
3. **别让它"顺手优化"别人的模块**——冲突和返工都从这来。
4. **别信"我改好了"**——要证据：网址、检查输出、改了哪些文件。
5. **别把密码、token 贴进对话**——要贴也只贴报错信息。
6. **别自己动 GitHub 的 Settings / 分支保护**——那是 P1 的活。
7. **别改已经推上去的数据库迁移文件**——会让别人的库对不上。
8. **别两个人同时改同一个目录**——先问一句"这块有人在做吗"。
9. **别在 CI 红的时候点合并**。
10. **别硬扛**：卡超过 2 小时就问，问的时候带上"我在做什么/期望什么/实际什么"。

---

## 11. 出事了怎么退回

| 情况 | 怎么办（对 agent 说） |
|---|---|
| 改乱了，想全部回到干净状态 | 「把我本地没提交的改动全部丢掉，回到和远端 main 一致」 |
| 提交错了、但还没合并 | 「把这个分支删掉，我们从 main 重新开始」 |
| 已经合并了才发现坏了 | 「main 上那个改动有问题，帮我用一次 revert 撤销它，然后开 PR」 |
| 不确定该不该动 | 「先别动，告诉我现状和三个可选方案，我来选」 |

---

## 12. 每天怎么过（很短）

1. **开工**：DSH 里说「帮我同步到最新，然后告诉我今天我能做的卡有哪些」；
2. **干活**：一次一张卡，第 6 节的模板照抄；
3. **验收**：第 7 节的 5 条检查；
4. **收尾**：点 Merge，然后在群里说一句"#12 已合并"；
5. **卡住**：2 小时没进展就问 P1。
